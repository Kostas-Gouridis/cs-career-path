# CS Career Path

Τεστ καριέρας για φοιτητές πληροφορικής: απαντάς πώς σκέφτεσαι και δουλεύεις, και βλέπεις ποιες από **12 κατευθύνσεις** σου ταιριάζουν.

Live: [cscareerpath.vercel.app](https://cscareerpath.vercel.app)

Ελληνικά και αγγλικά. Χωρίς εγγραφή, χωρίς email. Next.js, Supabase, Vercel.

## Τα δύο τεστ

Δύο ανεξάρτητες τράπεζες ερωτήσεων — καμία ερώτηση δεν είναι κοινή.

| | Σύντομο | Πλήρες |
| --- | --- | --- |
| Ερωτήσεις | 20 (`s01…s20`) | 60 (`q01…q60`) |
| Διάρκεια | 2–3 λεπτά | ~10 λεπτά |
| Μορφή | Μικρές ερωτήσεις ενστίκτου, σύντομες επιλογές | Δηλώσεις αυτοαξιολόγησης, πενταβάθμια κλίμακα («Συμφωνώ απόλυτα» … «Διαφωνώ απόλυτα») |
| Αποτέλεσμα | Πρώτη εικόνα | Καθαρότερη κατεύθυνση |

Και τα δύο δίνουν κατάταξη στις 12 καριέρες, προφίλ 8 διαστάσεων, roadmap, PDF και μόνιμο link. Το progress αποθηκεύεται τοπικά, ξεχωριστά ανά τεστ.

## Οι 12 κατευθύνσεις

Frontend · Backend · Mobile · Data Engineer · Data Scientist / Analyst · ML / AI · DevOps / Cloud · Cybersecurity · QA / Test Automation · Embedded / Systems · Product Manager · Έρευνα / Ακαδημαϊκή καριέρα

## Γρήγορη εκκίνηση

```bash
npm install
cp .env.example .env.local     # άλλαξε ΟΠΩΣΔΗΠΟΤΕ τον ADMIN_PASSWORD
npm run dev                    # http://localhost:3000
```

Η βάση είναι **Supabase** (Postgres). Τρέξε μία φορά το `supabase/schema.sql` στο SQL Editor του project.

| Μεταβλητή | Τι κάνει |
| --- | --- |
| `ADMIN_PASSWORD` | Κωδικός για το `/admin`. |
| `ADMIN_SECRET` | Υπογράφει το cookie του admin. Τυχαία συμβολοσειρά 32+ χαρακτήρων. |
| `SUPABASE_URL` | Το URL του project. |
| `SUPABASE_SERVICE_ROLE_KEY` | Το **service_role** key — όχι το anon. Μόνο server-side. |

## Σελίδες

| Διαδρομή | Τι είναι |
| --- | --- |
| `/` | Επιλογή τεστ, αποθηκευμένα αποτελέσματα της συσκευής, οι 12 κατευθύνσεις. |
| `/test?mode=short` | Σύντομο: 2 ενότητες × 10. |
| `/test?mode=full` | Πλήρες: 6 ενότητες × 10. Autosave ανά τεστ. |
| `/results/[id]` | Top 3, κατάταξη στις 12, radar chart, roadmap, PDF, share link. |
| `/privacy` | Πολιτική απορρήτου. |
| `/admin` | Ανώνυμα στατιστικά. Ζητά τον `ADMIN_PASSWORD`. |

## Πώς βαθμολογείται

Κάθε επιλογή δίνει βάρη ταυτόχρονα σε **καριέρες** και σε **traits** — π.χ. `c: { backend: 3, devops: 2 }`, `t: { systems: 3 }`. Οι ερωτήσεις δεν χωρίζονται σε «τεχνικές» και «προσωπικότητας» μπροστά στον χρήστη: η ετικέτα θα έλεγε τι μετράμε και θα αλλοίωνε την απάντηση.

1. Αθροίζονται τα βάρη όλων των απαντήσεων (`src/lib/scoring.ts`).
2. Για κάθε καριέρα υπολογίζονται, **ξεχωριστά ανά τεστ**, το θεωρητικό μέγιστο και το «σκορ της τύχης» (τι θα μάζευες απαντώντας στα τυφλά). Το ποσοστό είναι πόσο πάνω από την τύχη είσαι, ώστε καριέρες που εμφανίζονται σε πολλές ερωτήσεις να μη μαζεύουν πόντους τζάμπα.
3. Η κλίμακα τεντώνεται ώστε το πρώτο αποτέλεσμα να φτάνει κοντά στο 95%.

Τα traits κανονικοποιούνται το ίδιο: 50% σημαίνει «όσο ο μέσος όρος» και τροφοδοτούν το radar chart. Κάτω από 8 μονάδες διαφορά πρώτης–δεύτερης, το αποτέλεσμα δηλώνεται ως αναποφάσιστο.

Αν προσθέσεις ή αφαιρέσεις ερωτήσεις, τα σημεία αναφοράς εκείνου του τεστ ξαναϋπολογίζονται μόνα τους.

## Από πού προκύπτουν οι ερωτήσεις

Ο σχεδιασμός πατάει σε τρία πράγματα από τη βιβλιογραφία των τεστ επαγγελματικού προσανατολισμού:

- **RIASEC (Holland)** — έξι τύποι ενδιαφέροντος. Αντιστοιχίζονται χαλαρά στις 8 διαστάσεις του προφίλ· π.χ. frontend τραβάει Artistic–Investigative, backend/υποδομές Investigative–Realistic, product Enterprising–Social.
- **O\*NET Work Styles & Work Values** — προσοχή στη λεπτομέρεια, προσαρμοστικότητα, αντοχή στην πίεση, ανεξαρτησία. Αρκετές δηλώσεις ρωτούν ακριβώς αυτά, με καθημερινά παραδείγματα.
- **Ανοχή στην αβεβαιότητα / need for closure** — πόσο αντέχεις να μην έχεις σίγουρη απάντηση. Ξεχωρίζει καλύτερα έρευνα/ML από QA/υποδομές.

Οι δηλώσεις **αναμειγνύονται** αντί να ομαδοποιούνται ανά διάσταση: στο O\*NET Interest Profiler η ανάμειξη μειώνει το response bias (να απαντά κανείς «σωστά» επειδή κατάλαβε τι μετριέται). Γι' αυτό οι ενότητες του πλήρους τεστ λέγονται «1–10», «11–20» κ.ο.κ. — δεν είναι θεματικές.

## Δομή περιεχομένου

```
src/lib/
  careers.ts              12 καριέρες: περιγραφή, καθημερινότητα, tech, μαθήματα,
                          projects, πιστοποιήσεις, αγορά
  traits.ts               οι 8 διαστάσεις του προφίλ
  questions/section1..6   πλήρες τεστ (q01…q60)
  questions/short.ts      σύντομο τεστ (s01…s20)
  questions/index.ts      sectionsFor(mode), questionsFor(mode)
  scoring.ts              βαθμολόγηση
  db.ts                   Supabase: αποθήκευση + στατιστικά
  auth.ts                 admin login με HMAC-υπογεγραμμένο cookie
  i18n.ts                 κείμενα UI σε EL/EN
```

Τα ids δεν συγκρούονται (`s` vs `q`)· το `index.ts` πετάει αν ποτέ συμπέσουν.

**Πώς αλλάζεις μια ερώτηση.** Άνοιξε το αρχείο της ενότητας και άλλαξε κείμενο ή βάρη. **Μην αλλάξεις τα `id`** αν έχεις ήδη υποβολές — τα στατιστικά του `/admin` κλειδώνουν πάνω σε αυτά. Νέα ερώτηση = νέο `id` (π.χ. `q61`, `s21`).

Το `/admin` δείχνει μέσο ταίριασμα ανά καριέρα: αν μία βγαίνει πάντα πολύ ψηλά ή πολύ χαμηλά, τα βάρη της θέλουν ρύθμιση.

## Ιδιωτικότητα

Αποθηκεύονται μόνο: τυχαίο id, απαντήσεις, βαθμολογίες, γλώσσα, mode και διάρκεια. Καμία IP χρήστη, κανένα user-agent, κανένα email, κανένα cookie ταυτοποίησης. Ο πίνακας `starts` κρατά μετρητή εκκινήσεων για το ποσοστό εγκατάλειψης.

Λεπτομέρειες στο [`/privacy`](https://cscareerpath.vercel.app/privacy).

## Deploy

Δουλεύει σε Vercel ως έχει: όλη η κατάσταση ζει στο Supabase, οπότε το εφήμερο filesystem των serverless functions δεν πειράζει.

1. Τρέξε το `supabase/schema.sql` στο SQL Editor του Supabase.
2. Βάλε στο Vercel τα τέσσερα env vars του πίνακα παραπάνω (Production + Preview).
3. Deploy.

Η επισκεψιμότητα καταγράφεται από το Vercel Analytics. Τα στατιστικά του ίδιου του τεστ ζουν στο `/admin`.

## Έλεγχοι

- `npm run build` περνάει (types).
- Υποβολή και των δύο τεστ → αποθήκευση → αποτελέσματα → admin.
- Ελλιπής υποβολή και άκυρο option id → 400. Απαντήσεις του ενός τεστ ως το άλλο → 400.
- Προσομοίωση: απαντώντας «υπέρ» κάθε καριέρας, βγαίνει #1 και στα δύο τεστ.
- Τυχαίες απαντήσεις: καμία καριέρα δεν βγαίνει πρώτη πάνω από ~12% των φορών (ιδανικό 8,3%).
- `/api/admin/stats` χωρίς cookie ή με λάθος κωδικό → 401.
